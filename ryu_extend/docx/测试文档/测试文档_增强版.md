# SDN IoT 控制器增强版测试文档

## 1. 测试环境

### 1.1 硬件环境
- 操作系统: Linux (Ubuntu 20.04 或更高版本)
- 内存: 至少 4GB RAM
- 硬盘: 至少 20GB 可用空间

### 1.2 软件环境
- Python 3.8+
- Ryu SDN 控制器框架
- Mininet 网络仿真器
- Open vSwitch 2.13+
- Flask Web 框架

### 1.3 依赖安装
```bash
pip install ryu flask requests
sudo apt-get install mininet openvswitch-switch
```

## 2. 测试项目

### 2.1 OpenFlow 1.3 协议支持测试

#### 2.1.1 流表下发测试
**测试目的**: 验证控制器能够成功下发 OpenFlow 1.3 流表到交换机

**测试步骤**:
1. 启动 Ryu 控制器: `ryu-manager switch/ble_switch_13.py`
2. 启动 Mininet 拓扑: `sudo python3 topology/iot_sdn_topology.py`
3. 在 Mininet 中执行: `h1 ping h2`
4. 检查交换机流表: `sudo ovs-ofctl dump-flows s1 -O OpenFlow13`

**预期结果**:
- 交换机 s1 和 s2 上能够看到安装的流表
- 流表包含正确的匹配条件和动作
- ping 命令能够正常执行

**通过标准**: 流表正确下发，网络连通正常

#### 2.1.2 统计收集测试
**测试目的**: 验证控制器能够定期收集交换机的统计信息

**测试步骤**:
1. 启动控制器和 Mininet 拓扑
2. 生成网络流量 (如: `h1 ping h2 -c 100`)
3. 等待 10 秒 (统计收集间隔)
4. 访问 Web 面板统计页面

**预期结果**:
- 端口统计显示正确的收发数据包数
- 流表统计显示流表匹配次数
- 表统计显示活跃流表数量

**通过标准**: 统计数据准确且定期更新

### 2.2 拓扑管理测试

#### 2.2.1 自动拓扑发现测试
**测试目的**: 验证控制器能够通过 LLDP 自动发现网络拓扑

**测试步骤**:
1. 启动控制器和 Mininet 拓扑
2. 等待 10 秒 (LLDP 发送间隔)
3. 访问 Web 面板拓扑页面

**预期结果**:
- 拓扑中显示所有交换机
- 拓扑中显示交换机之间的链接
- 拓扑中显示连接的主机

**通过标准**: 拓扑结构正确显示

#### 2.2.2 拓扑可视化测试
**测试目的**: 验证 Web 面板能够正确可视化网络拓扑

**测试步骤**:
1. 访问增强版 Web 面板: `http://localhost:5000/enhanced`
2. 点击"拓扑可视化"标签页

**预期结果**:
- 拓扑图显示交换机、主机和链接
- 节点有正确的颜色区分 (交换机: 蓝色, 主机: 绿色)
- 节点有正确的标签
- iot1、iot2、iot4 连接到 iot3 网关，iot3 再连接到 s1 交换机
- 拓扑连接关系正确：s1 <-> s2, s2 <-> h1, s2 <-> h2, s1 <-> iot3, iot3 <-> iot1, iot3 <-> iot2, iot3 <-> iot4

**通过标准**: 拓扑图清晰美观，信息准确，连接关系正确

### 2.3 流表管理测试

#### 2.3.1 流表增删改查测试
**测试目的**: 验证流表的增删改查功能

**测试步骤**:
1. 访问增强版 Web 面板
2. 点击"流表管理"标签页
3. 添加新流表: 选择交换机 s1, 表 ID 0, 优先级 100, 匹配条件 `eth_type=0x0800,ipv4_dst=192.168.1.20`, 动作 `output:2`
4. 点击"添加流表"
5. 检查流表是否添加成功
6. 点击"清空流表"删除所有流表

**预期结果**:
- 流表添加成功提示
- 流表列表显示新添加的流表
- 清空后流表列表为空

**通过标准**: 所有操作正常执行

#### 2.3.2 多级流表测试
**测试目的**: 验证多级流表功能

**测试步骤**:
1. 添加流表到表 ID 1
2. 添加流表到表 ID 2
3. 检查不同表 ID 的流表

**预期结果**:
- 不同表 ID 的流表能够独立管理
- 流表统计能够区分不同表 ID

**通过标准**: 多级流表功能正常

## 3.3 数据传输测试

#### 3.3.1 方式一：通过网关直接发送
**测试目的**: 验证 IoT 设备直接发送数据到目标主机的功能

**测试步骤**:
1. 在 h1 和 h2 上启动监听: `mininet> xterm h1 h2`，然后分别执行 `nc -ul 5005`
2. 从 iot1 发送数据到 h1: `mininet> iot1 echo "aa:bb:cc:dd:ee:01,temp,25.5" | nc -u 192.168.1.20 5005`
3. 从 iot2 发送数据到 h2: `mininet> iot2 echo "aa:bb:cc:dd:ee:02,humidity,65.3" | nc -u 192.168.1.21 5005`
4. 从 iot4 发送数据到 h1: `mininet> iot4 echo "aa:bb:cc:dd:ee:04,pos,(30.12,120.45)" | nc -u 192.168.1.20 5005`
5. 检查 h1 和 h2 是否收到数据

**预期结果**:
- h1 收到 iot1 和 iot4 的数据
- h2 收到 iot2 的数据
- 控制器显示流表下发记录

**通过标准**: 所有数据传输成功

## 5. 故障排查

### 5.1 常见问题

**问题**: 控制器无法连接交换机
**解决方案**: 检查控制器和交换机的 IP 地址是否正确，确保防火墙没有阻止 6634 端口

**问题**: 拓扑无法发现
**解决方案**: 检查 LLDP 数据包是否能够正常发送和接收，确认交换机支持 LLDP

**问题**: 统计数据不更新
**解决方案**: 检查统计收集线程是否正常运行，确认 OpenFlow 1.3 统计请求能够正常发送

### 5.2 日志查看
- 控制器日志: 控制器启动时的控制台输出
- Web 面板日志: `http://localhost:5000/health`
- 交换机日志: 使用 `ovs-appctl vlog/list` 查看
