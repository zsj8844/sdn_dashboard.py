### 场景B工作原理说明

#### 为什么发送到网关后能直接转发给h1/h2？

IoT网关（iot3）是一个**应用层智能网关**，不是简单的网络层NAT转发。工作流程如下：

1. **接收数据**：网关在 `0.0.0.0:5005` 监听所有接口的UDP数据包
2. **解析数据**：提取BLE地址、传感器类型、数据值
   - 数据格式：`BLE地址,传感器类型,数据值`
   - 例如：`aa:bb:cc:dd:ee:01,temp,25.5`
3. **编码OpenFlow扩展**：根据数据类型和值计算优先级，编码成OpenFlow Experimenter扩展字段
4. **发送到控制器**：将扩展信息通过UDP发送给控制器（127.0.0.1:6650）
5. **智能转发决策**：根据BLE地址选择目标主机
   - `aa:bb:cc:dd:ee:01` 或 `aa:bb:cc:dd:ee:04` → 转发到 `192.168.1.20` (h1)
   - `aa:bb:cc:dd:ee:02` → 转发到 `192.168.1.21` (h2)
   - 其他 → 默认转发到 `192.168.1.20` (h1)
6. **转发数据**：通过UDP socket直接将数据发送到目标主机的5005端口

**关键区别**：
- 场景A：iot1 → SDN网络 → h1（纯网络层转发）
- 场景B：iot1 → 网关应用层处理 → h1（应用层智能转发+OpenFlow扩展）

## 故障排查

### 常见问题

1. **iptables NAT配置失败**
   - 检查iptables规则：`mininet> iot3 iptables -t nat -L -n -v`
   - 检查IP转发：`mininet> iot3 sysctl net.ipv4.ip_forward`

2. **IoT设备无法发送数据（场景A - 直接转发）**
   - 检查网络连通性：`mininet> iot1 ping -c 1 192.168.1.20`
   - 确认数据发送到正确的目标主机（h1/h2）

3. **IoT网关无法接收数据（场景B - 网关处理）**
   - 检查网关是否运行：`mininet> iot3 ps aux | grep iot_gateway`
   - 检查网关监听：`mininet> iot3 netstat -ulnp | grep 5005`
   - 查看网关日志：`mininet> iot3 tail -f /home/zhang/桌面/ryucontronl2/ryu_extend/logs/gateway.log`
   - 确认数据发送到网关的对应接口IP（192.168.2.1/192.168.3.1/192.168.4.1）

4. **数据转发失败**
   - 检查交换机流表：`mininet> sh ovs-ofctl dump-flows s1 -O OpenFlow13`
   - 检查控制器日志

5. **Web面板无日志**
   - 检查控制器是否正确推送日志
   - 检查Web面板是否正常运行

6. **网关日志没有记录**
   - 确认数据发送到网关IP，不是h1/h2
   - 检查网关日志文件：`ls -l /home/zhang/桌面/ryucontronl2/ryu_extend/logs/`
   - 重新启动网关程序

### 调试命令

- 查看控制器日志：在控制器终端查看
- 查看交换机流表：`ovs-ofctl dump-flows s1 -O OpenFlow13`
- 检查iptables规则：`mininet> iot3 iptables -t nat -L -n -v`
- 查看网关日志：`mininet> iot3 tail -f /home/zhang/桌面/ryucontronl2/ryu_extend/logs/gateway.log`
- 抓包分析：`mininet> iot3 xterm` 然后运行 `tcpdump -i any -n 'udp port 5005'`
