# SDN IoT 控制器增强版功能说明文档

## 1. 系统概述

### 1.1 项目背景
本项目是基于 Ryu 控制器框架的 SDN (软件定义网络) IoT (物联网) 控制器增强版，在原有基础上增加了 OpenFlow 1.3 协议支持、拓扑管理和流表管理三大核心功能。

## 2. 核心功能详解

### 2.1 OpenFlow 1.3 协议支持

#### 2.1.1 流表下发
**功能描述**: 支持向交换机下发 OpenFlow 1.3 流表规则

**技术实现**:
- 使用 `ryu.ofproto.ofproto_v1_3` 模块
- 通过 `OFPFlowMod` 消息下发流表
- 支持多级流表 (Table ID 0-254)
- 支持优先级、超时时间等参数

**关键代码**:
```python
def add_flow(self, datapath, priority, match, actions, idle_timeout=0, hard_timeout=0, table_id=0):
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser
    inst = [parser.OFPInstructionActions(ofproto.OFPIT_APPLY_ACTIONS, actions)]
    mod = parser.OFPFlowMod(
        datapath=datapath, table_id=table_id, priority=priority, match=match,
        instructions=inst, idle_timeout=idle_timeout, hard_timeout=hard_timeout
    )
    datapath.send_msg(mod)
```

#### 2.1.2 统计收集
**功能描述**: 定期收集交换机的端口统计、流表统计和表统计

**技术实现**:
- 使用独立线程定期发送统计请求
- 支持三种统计类型:
  - 端口统计 (OFPPortStatsRequest)
  - 流表统计 (OFPFlowStatsRequest)
  - 表统计 (OFPTableStatsRequest)
- 默认收集间隔: 10 秒

**关键代码**:
```python
def _stats_collector(self):
    while True:
        hub.sleep(self.stats_interval)
        for dpid, datapath in list(self.topology['switches'].items()):
            try:
                self.request_port_stats(datapath)
                self.request_flow_stats(datapath)
                self.request_table_stats(datapath)
            except Exception as e:
                self.logger.warning(f"收集交换机 {dpid} 统计失败: {e}")
```

### 2.2 拓扑管理

#### 2.2.1 自动拓扑发现
**功能描述**: 使用 LLDP (链路层发现协议) 自动发现网络拓扑

**技术实现**:
- 定期从每个交换机端口发送 LLDP 数据包
- 处理收到的 LLDP 数据包，建立链路关系
- 维护交换机、主机和链接的拓扑数据结构
- 默认 LLDP 发送间隔: 5 秒

**LLDP 数据包结构**:
- Chassis ID: 交换机 MAC 地址
- Port ID: 端口号
- TTL: 10 秒
- System Name: 交换机名称 (switch-{dpid})

**关键代码**:
```python
def _handle_lldp_packet(self, dpid, in_port, pkt):
    lldp_pkt = pkt.get_protocol(lldp.lldp)
    if not lldp_pkt:
        return
    
    chassis_id = None
    port_id = None
    system_name = None
    
    for tlv in lldp_pkt.tlvs:
        if tlv.tlv_type == lldp.lldp.LLDP_TLV_CHASSIS_ID:
            chassis_id = tlv.chassis_id
        elif tlv.tlv_type == lldp.lldp.LLDP_TLV_PORT_ID:
            port_id = tlv.port_id
        elif tlv.tlv_type == lldp.lldp.LLDP_TLV_SYSTEM_NAME:
            system_name = tlv.system_name
    
    if chassis_id and port_id and system_name:
        src_switch = system_name.decode('utf-8')
        src_port = int(port_id.decode('utf-8'))
        dst_switch = f'switch-{dpid}'
        dst_port = in_port
```

#### 2.2.2 拓扑可视化
**功能描述**: 使用 D3.js 在 Web 面板中可视化网络拓扑

**技术实现**:
- 使用 D3.js v7 绘制 SVG 图形
- 节点类型:

### 2.3 流表管理

#### 2.3.1 流表 CRUD
**功能描述**: 提供流表的增删改查功能

**功能列表**:
- **添加流表**: 支持指定表 ID、优先级、匹配条件和动作
- **删除流表**: 支持按表 ID 删除或清空所有流表
- **修改流表**: 支持修改现有流表
- **查询流表**: 支持查询指定交换机或指定表 ID 的流表

**关键代码**:
```python
def delete_flow(self, datapath, match=None, priority=None, table_id=0):
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser
    
    if match is None:
        match = parser.OFPMatch()
    
    mod = parser.OFPFlowMod(
        datapath=datapath,
        table_id=table_id,
        priority=priority if priority is not None else ofproto.OFP_DEFAULT_PRIORITY,
        match=match,
        command=ofproto.OFPFC_DELETE,
        out_port=ofproto.OFPP_ANY,
        out_group=ofproto.OFPG_ANY
    )
    datapath.send_msg(mod)
```

#### 2.3.2 多级流表
**功能描述**: 支持 OpenFlow 1.3 的多级流表功能

**技术实现**:
- 支持 Table ID 0-254
- 流表按 Table ID 独立管理
- 统计数据按 Table ID 分类
- 支持流表之间的跳转 (Goto-Table 指令)

### 2.4 应用下发功能

#### 2.4.1 边缘应用管理
**功能描述**: 提供完整的边缘应用生命周期管理，包括应用创建、封装、部署、卸载

**技术实现**:
- 支持多种应用类型：数据过滤、AI推理、数据聚合、自定义
- 应用状态管理：未部署、部署中、运行中、已停止、错误
- 应用代码校验：SHA256校验和确保代码完整性
- 部署历史记录：记录所有应用部署和卸载操作

**应用类型**:
1. **DATA_FILTER (1)**: 数据过滤应用
2. **AI_INFERENCE (2)**: AI推理应用
3. **DATA_AGGREGATION (3)**: 数据聚合应用
4. **CUSTOM (4)**: 自定义应用

**关键代码位置**:
- `switch/extensions/app_deployment.py`: 应用部署核心模块
- `ble_switch_13.py:create_edge_application()`: 创建边缘应用
- `ble_switch_13.py:deploy_application_to_device()`: 部署应用到设备

### 2.5 角色切换功能

#### 2.5.1 设备模式管理
**功能描述**: 支持设备模式动态切换，提供纯转发、计算混合、物联网网关三种模式

**技术实现**:
- 三种设备模式：纯转发、计算混合、物联网网关
- 设备能力描述：CPU核心数、内存、GPU支持、协议支持等
- 模式切换检查：切换前验证设备能力是否支持目标模式
- 模式识别：基于流量模式和资源使用自动识别最优模式
- 切换历史记录：记录所有模式切换操作

**设备模式**:
1. **PURE_FORWARDING (1)**: 纯转发模式 - 专注于数据转发
2. **COMPUTE_HYBRID (2)**: 计算混合模式 - 同时支持转发和边缘计算
3. **IOT_GATEWAY (3)**: 物联网网关模式 - 专门处理IoT设备数据

**关键代码位置**:
- `switch/extensions/role_switch.py`: 角色切换核心模块
- `ble_switch_13.py:register_device_with_role()`: 注册设备并设置角色
- `ble_switch_13.py:switch_device_role()`: 切换设备角色
- `ble_switch_13.py:identify_device_mode()`: 识别设备最优模式

4. **Web 面板扩展**: 新增 Flask 路由和 HTML 模板

## 6. 性能考虑

### 6.1 性能优化建议
1. **统计收集间隔**: 根据网络规模调整，建议 5-30 秒
2. **流表超时**: 合理设置 idle_timeout，避免流表爆炸
3. **多级流表**: 使用多级流表减少单表流表数量
4. **Web 面板缓存**: 对不常变化的数据进行缓存

### 6.2 性能指标
- 支持交换机数量: 最多 100 台 (取决于硬件)
- 流表容量: 取决于交换机硬件
- 统计延迟: < 1 秒 (局域网内)
- 拓扑发现时间: < 15 秒

## 7. 安全考虑

### 7.1 安全建议
1. **网络隔离**: 将控制器和交换机放在独立的管理网络
2. **访问控制**: 使用防火墙限制对控制器的访问
3. **加密**: 生产环境建议使用 TLS 加密 OpenFlow 连接
4. **认证**: 考虑使用 OpenFlow 1.3 的 TLS 认证

### 7.2 日志和审计
- 控制器日志记录所有流表操作
- Web 面板记录所有 API 调用
- 建议定期备份日志
