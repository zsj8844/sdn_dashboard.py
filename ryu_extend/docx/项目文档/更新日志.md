## v4.5.2 (2026-07-21) — ARP崩溃修复 + 主动流表模式 + 主机发现

**修复内容**:
1. **ARP 包导致控制器崩溃**：`_forward()` 中 `ip_dst = ip_pkt.src` 在 ARP 包（`ip_pkt=None`）时抛出 AttributeError，阻止 ARP 解析 → ICMP 永远发不出
2. **主动流表预装**：交换机连接后控制器自动下发双向 IPv4 流表（5条/s1 + 5条/s2），不再依赖被动 Packet-In 反应式建流表
3. **ARP 主机发现**：主动流表模式下 IPv4 包不再触发 Packet-In → 从 ARP 包提取 IP/MAC 做 `discover_device()`，恢复拓扑主机显示
4. **网关 `_request_flow_setup()` 移除**：iot3 在 Mininet 命名空间内无法访问宿主机 `127.0.0.1:16634`，该重试逻辑无效已删除
5. **文档更新**：`nc -u` 加 `-w 1` 防卡死，故障排查 + 问题记录
6. **代码模块化**：将 Packet-In 处理、BLE 解析、转发逻辑从 `ble_switch_13.py` (412行) 拆出 `packet_processor.py` (196行)，主控制器缩至 236 行

**Bug 分析**:
| Bug | 位置 | 现象 | 修复 |
|-----|------|------|------|
| ARP None 崩溃 | `ble_switch_13.py:_forward()` | 控制台无报错但 ping 全丢 | `ip_pkt` 判 None，ARP 走泛洪 |
| 被动模式来不及 | 无主动流表 | 6s 内 4 跳 Packet-In 全超时 | 交换机连接时预装流表 |
| 拓扑无主机 | 无 ARP 发现 | Vue 拓扑只显示交换机 | 从 ARP 包提取 src_ip 做发现 |

**修改文件**:
| 文件 | 说明 |
|------|------|
| `switch/ble_switch_13.py` | 模块化重构（412→236行），委托 PacketProcessor 处理 Packet-In |
| `switch/Other_Modules/packet_processor.py` | **新增**：Packet-In 全流程处理（解析→ARP发现→BLE解析→转发→流表） |
| `switch/Other_Modules/infra/control_http.py` | 新增 `install_default_flows()` + `/install-all` `/install-path` 端点 |
| `switch/Other_Modules/__init__.py` | 导出 PacketProcessor |
| `topology/iot_gateway_enhanced.py` | 移除无效的 `_request_flow_setup()` 和 `import urllib.request` |
| `docx/项目文档/安装与启动.md` | `nc -u` 加 `-w 1`，更新故障排查 |
| `docx/项目文档/更新日志.md` | 新增 v4.5.2 |

## v4.5.1 (2026-07-21) — IoT 跨子网连通性修复

**修复内容**:
1. **iot3 网关添加 MASQUERADE NAT 规则**：IoT 子网 (192.168.2.0/24, 192.168.3.0/24, 192.168.4.0/24) 流量经 eth3 出口时自动做源地址转换，以 192.168.1.12 身份访问外部网络
2. **路由引擎添加 IoT 子网回程路由**：route_engine.py 添加 192.168.2.x/3.x/4.x 设备 IP 的显式路由，NAT 失效时作为兜底
3. **连接跟踪模块加载**：modprobe nf_conntrack/nf_conntrack_ipv4 确保回程包能正确 de-NAT

**修复前问题**:
- iot1/iot2/iot4 到 h1/h2 (192.168.1.20/21) ping 不通
- 根因：iot3 缺少 SNAT/MASQUERADE 规则，IoT 源 IP 暴露给外部网络
- 回程流量目的 IP (192.168.2.x/3.x/4.x) 在 route_engine 中无匹配路由，降级为泛洪

**修改文件**:
| 文件 | 说明 |
|------|------|
| `topology/iot_sdn_topology.py` | iot3 添加 MASQUERADE + conntrack 模块加载 |
| `switch/Other_Modules/topology/route_engine.py` | 添加 IoT 子网设备 IP 回程路由 |

## v4.0.0 (2026-02-24) — 架构简化（纯NAT网关）

**重大架构变更 — 纯NAT网关模式**:

1. **移除网关模拟器**：完全删除 `iot_gateway_simulator.py`，使用纯 iptables NAT 转发
2. **直接发送模式**：IoT设备直接发送数据到目标主机，通过 iot3 NAT 转发
3. **控制器优化**：简化流表下发逻辑，确保所有IP数据包正确处理

**新数据流向**:
```
IoT设备 → iot3 (NAT网关+iptables) → s1 → s2 → h1/h2
```

**测试命令更新**:
```bash
# 直接发送到目标主机
mininet> iot1 echo "..." | nc -u 192.168.1.20 5005
mininet> iot2 echo "..." | nc -u 192.168.1.21 5005
mininet> iot4 echo "..." | nc -u 192.168.1.20 5005
```

**架构优势**：复杂度降低，iot1和iot4可正常发送，无网络转发干扰，更符合真实网络架构。
