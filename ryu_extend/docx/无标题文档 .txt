物联网 SDN 实验环境搭建与成果文档
一、项目背景
软件定义网络（SDN）通过 “控制平面与数据平面分离” 的架构，为物联网（IoT）场景提供了集中化控制、灵活流量调度、全局视图管理的能力。本实验旨在搭建一套基于 OpenFlow 协议的物联网 SDN 环境，实现对物联网设备（传感器、网关）与传统主机的统一控制、流量可视化与连通性管理，为后续物联网协议扩展、路径优化等研究奠定基础。
二、实验环境架构
本实验环境采用 **“控制器 - 交换机 - 终端设备”** 三层架构，各组件及功能如下：
组件类型	具体实现	功能说明
控制器	Ryu（simple_switch_13）	基于 OpenFlow 1.3 协议，集中控制交换机流表，实现设备间流量转发规则的下发与管理。
交换机	Open vSwitch（OVS）	虚拟交换机，支持 OpenFlow 协议，根据控制器下发的流表执行数据包转发。
终端设备	Mininet 虚拟拓扑	包含物联网设备（iot1 - 温度传感器、iot2 - 湿度传感器、iot3 - 网关）和传统主机（h1、h2），模拟真实物联网组网场景。
可视化面板	自定义 Flask Web 应用	实时展示设备清单、网络连通性、MQTT 物联网消息、OpenFlow 流表，实现实验环境的可视化监控。
三、已完成工作与技术细节

2. 设备兼容：支持虚拟交换机（OVS）

流表输出包含dl_src（源 MAC）、dl_dst（目的 MAC）、actions（转发动作）等字段，说明 OVS 已成功接收并执行控制器的流表指令。
3. OpenFlow 协议下达：断点续传与设备适配
控制器（Ryu）与交换机（OVS）基于 OpenFlow 1.3 协议通信，支持流表的动态下发与持久化。即使设备短暂中断（如重启交换机），控制器也能自动重新建立连接，并恢复流表规则，实现 “断点续传” 的协议下达能力。
通过流表计数器（n_packets、n_bytes）可验证流量的持续转发：

cookie=0x0, duration=xxx, table=0, n_packets=5, n_bytes=420, priority=1,dl_src=xx:xx:xx:xx:xx:xx,dl_dst=xx:xx:xx:xx:xx:xx actions=output:xx

    MQTT 消息日志：实时接收物联网设备的传感器消息（如温度、湿度）；
    交换机流表：实时展示 s1、s2 交换机的前 10 条流表，辅助流表分析。

四、技术难点与解决方案
1. 连通性检测的 MAC 地址动态匹配问题
难点：Mininet 每次重启拓扑会随机分配设备 MAC 地址，导致静态配置的 MAC 匹配逻辑失效。
解决方案：开发基于流表自动识别的连通性检测逻辑，通过正则解析 OpenFlow 流表中的dl_src、dl_dst和n_packets字段，自动识别有流量的设备通信对，实现连通性状态的动态更新。
2. Web 面板与底层环境的权限与通信问题
难点：Web 面板（Flask）需要执行sudo权限的流表查询命令，且需实时同步底层环境的状态。
解决方案：通过 Python 的subprocess模块封装带sudo的流表查询命令，并结合多线程技术（threading）实现 MQTT 消息订阅、连通性检测、Web 服务的并行运行。
五、未来工作展望

    OpenFlow 协议扩展调研：研究 OpenFlow 1.5 及以上版本的新特性（如组表、多控制器支持），探索其在物联网场景的适配与扩展；
    协议兼容性研究：尝试在 OpenFlow 协议中兼容 CoAP、MQTT 等物联网协议，实现 “控制平面 - 数据平面” 的协议统一；
    路径决策与优化：引入最短路径、负载均衡等算法，优化物联网设备的流量转发路径，提升网络性能；
    真实设备接入：将实验环境从虚拟拓扑扩展到真实物联网设备（如树莓派传感器、工业网关），验证 SDN 在真实场景的适用性。

六、总结
本实验已成功搭建一套 **“控制器 - 交换机 - 物联网设备”** 的 SDN 实验环境，实现了 OpenFlow 协议的集中控制、虚拟设备的兼容、流量的可视化监控等核心功能。该环境为后续物联网 SDN 的协议扩展、路径优化等研究提供了稳定的基础平台，具备较高的可扩展性与实用性。

2.3.1 自定义 Mininet 拓扑脚本（iot_sdn_topology.py）
在工作目录（如~/ryucontronl）创建拓扑脚本，定义交换机、设备与链路：

运行

from mininet.net import Mininet
from mininet.node import Controller, OVSKernelSwitch, Host
from mininet.link import TCLink
from mininet.cli import CLI
from mininet.log import setLogLevel

def create_iot_sdn_topology():
    # 创建网络（指定控制器为Ryu，交换机为OVS）
    net = Mininet(controller=Controller, switch=OVSKernelSwitch, link=TCLink)

    # 添加控制器（默认监听127.0.0.1:6633）
    c0 = net.addController('c0', controller=Controller, ip='127.0.0.1', port=6633)

    # 添加交换机（s1、s2）
    s1 = net.addSwitch('s1')
    s2 = net.addSwitch('s2')

    # 添加物联网设备（iot1、iot2、iot3）与传统主机（h1、h2）
    iot1 = net.addHost('iot1', ip='192.168.1.10/24')
    iot2 = net.addHost('iot2', ip='192.168.1.11/24')
    iot3 = net.addHost('iot3', ip='192.168.1.12/24')
    h1 = net.addHost('h1', ip='192.168.1.20/24')
    h2 = net.addHost('h2', ip='192.168.1.21/24')

    # 添加链路（配置带宽、延迟，消除sch_htb警告）
    net.addLink(iot1, s1, bw=10, delay='5ms', r2q=100)
    net.addLink(iot2, s1, bw=10, delay='5ms', r2q=100)
    net.addLink(iot3, s1, bw=100, delay='2ms', r2q=100)
    net.addLink(s1, s2, bw=1000, delay='1ms', r2q=100)
    net.addLink(h1, s2, bw=100, delay='1ms', r2q=100)
    net.addLink(h2, s2, bw=100, delay='1ms', r2q=100)

    # 启动网络
    net.start()

    # 关联控制器与交换机
    c0.start()
    s1.start([c0])
    s2.start([c0])

    # 启动命令行交互
    CLI(net)

    # 停止网络
    net.stop()

if __name__ == '__main__':
    setLogLevel('info')
    create_iot_sdn_topology()

python
运行

from flask import Flask, render_template, jsonify
import paho.mqtt.client as mqtt
import subprocess
import threading
import time
from collections import deque
import re

# 初始化Flask应用
app = Flask(__name__)

# ------------------------------
# 基础配置（和拓扑完全匹配）
# ------------------------------
DEVICES = {
    "控制器": ["c0 (Ryu, 127.0.0.1:6633)"],
    "交换机": ["s1 (OpenFlow13)", "s2 (OpenFlow13)"],
    "物联网设备": ["iot1 (温度传感器, 192.168.1.10)", "iot2 (湿度传感器, 192.168.1.11)", "iot3 (网关, 192.168.1.12)"],
    "传统主机": ["h1 (终端, 192.168.1.20)", "h2 (终端, 192.168.1.21)"]
}

# MQTT消息日志（最多存10条）
MQTT_LOG = deque(maxlen=10)
# 连通性状态（初始为空，由检测线程自动填充）
CONNECTIVITY_STATUS = {}  

# ------------------------------
# MQTT订阅（接收传感器消息）
# ------------------------------
MQTT_BROKER = "127.0.0.1"
MQTT_PORT = 1883
MQTT_TOPIC = "iot/sensor/#"

def on_mqtt_message(client, userdata, msg):
    message = msg.payload.decode("utf-8")
    topic = msg.topic
    timestamp = time.strftime("%H:%M:%S", time.localtime())
    MQTT_LOG.appendleft(f"[{timestamp}] 主题: {topic} → 消息: {message}")

def start_mqtt_subscriber():
    client = mqtt.Client()
    client.on_message = on_mqtt_message
    client.connect(MQTT_BROKER, MQTT_PORT, 60)
    client.subscribe(MQTT_TOPIC)
    client.loop_forever()

# ------------------------------
# 核心：流表解析与连通性检测
# ------------------------------
def get_switch_flows(switch_name):
    """获取交换机流表"""
    try:
        result = subprocess.run(
            ["sudo", "ovs-ofctl", "dump-flows", switch_name, "-O", "OpenFlow13"],
            capture_output=True, text=True, timeout=5
        )
        if result.returncode == 0:
            return [line.strip() for line in result.stdout.split("\n") if line.strip()]
        else:
            return []
    except Exception as e:
        print(f"获取{switch_name}流表失败: {e}")
        return []

def check_connectivity_by_flows():
    """自动识别流表中活跃MAC通信对"""
    while True:
        s1_flows = get_switch_flows("s1")
        s2_flows = get_switch_flows("s2")
        all_flows = s1_flows + s2_flows

        active_pairs = set()
        for flow in all_flows:
            if "dl_src=" in flow and "dl_dst=" in flow and "n_packets=" in flow:
                # 提取MAC与流量数
                src_mac = [part.split("=")[1] for part in flow.split(",") if part.strip().startswith("dl_src=")][0]
                dst_mac = [part.split("=")[1] for part in flow.split(",") if part.strip().startswith("dl_dst=")][0]
                packets_str = [part for part in flow.split(",") if part.strip().startswith("n_packets=")][0]
                packet_count = int(packets_str.split("=")[1])
                if packet_count > 0:
                    active_pairs.add((src_mac, dst_mac))

        # 更新连通性状态
        global CONNECTIVITY_STATUS
        CONNECTIVITY_STATUS = {}
        for src_mac, dst_mac in active_pairs:
            conn_name = f"{src_mac[:8]}... → {dst_mac[:8]}..."
            CONNECTIVITY_STATUS[conn_name] = "✅ 连通"
        if not CONNECTIVITY_STATUS:
            CONNECTIVITY_STATUS["暂无活跃通信"] = "⚠️  无流量"
        time.sleep(5)

# ------------------------------
# Web路由
# ------------------------------
@app.route("/")
def index():
    return render_template("dashboard.html", devices=DEVICES)

@app.route("/api/data")
def api_data():
    s1_flows = get_switch_flows("s1")[:10]
    s2_flows = get_switch_flows("s2")[:10]
    return jsonify({
        "mqtt_log": list(MQTT_LOG),
        "connectivity": CONNECTIVITY_STATUS,
        "s1_flows": s1_flows,
        "s2_flows": s2_flows
    })

# ------------------------------
# 启动服务
# ------------------------------
if __name__ == "__main__":
    # 启动MQTT订阅线程
    mqtt_thread = threading.Thread(target=start_mqtt_subscriber, daemon=True)
    mqtt_thread.start()
    print("✅ MQTT订阅线程启动成功")

    # 启动连通性检测线程
    connectivity_thread = threading.Thread(target=check_connectivity_by_flows, daemon=True)
    connectivity_thread.start()
    print("✅ 连通性检测线程启动成功（流表解析版）")

    # 启动Web服务器
    print("🌐 Web面板启动：http://localhost:5000")
    app.run(host="0.0.0.0", debug=True, use_reloader=False)

五、技术难点与解决方案
5.1 连通性检测的 MAC 地址动态匹配问题

    难点：Mininet 每次重启拓扑会随机分配设备 MAC 地址，静态配置的 MAC 匹配逻辑失效。
    解决方案：开发基于流表自动识别的连通性检测逻辑，通过解析流表中的dl_src、dl_dst和n_packets字段，自动识别有流量的设备通信对，无需手动配置 MAC。

5.2 Web 面板与底层环境的权限与通信问题

    难点：Web 面板需要执行sudo权限的流表查询命令，且需实时同步底层环境状态。
    解决方案：用 Python 的subprocess模块封装带sudo的流表查询命令，结合多线程技术实现 MQTT 消息订阅、连通性检测、Web 服务的并行运行。

5.3 流表字段解析格式问题

    难点：OpenFlow 流表的字段用逗号分隔，直接用空格拆分会导致 MAC 地址提取错误。
    解决方案：通过split(",")拆分流表字段，再过滤出dl_src、dl_dst等目标字段，确保提取准确性。
