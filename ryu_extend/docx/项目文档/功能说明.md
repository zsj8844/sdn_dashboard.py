## 1. OpenFlow 1.3 协议支持

### 1.1 流表下发模式

支持两种流表下发模式：

**主动模式（Proactive，当前使用）**：
交换机连接后控制器自动预装双向 IPv4 转发流表，数据包到达时直接命中流表硬件转发，无需触发 Packet-In。实现位置：`control_http.py:install_default_flows()`。

预装流表（每台交换机 5 条，priority=100）：
- s1: IoT子网IP → port1(iot3)，192.168.1.20/21 → port2(s2)
- s2: IoT子网IP → port1(s1)，192.168.1.20 → port2(h1)，192.168.1.21 → port3(h2)

**被动模式（Reactive，保留作为兜底）**：
Packet-In 到达时由 `_forward()` 查询路由并下发流表。流表带 `idle_timeout=60` 自动过期。

### 1.2 流表下发 API

**实现位置**: `switch/Other_Modules/infra/flow_manager.py`

```python
def add_flow(self, datapath, priority, match, actions,
             idle_timeout=0, hard_timeout=0, table_id=0):
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser

    inst = [parser.OFPInstructionActions(ofproto.OFPIT_APPLY_ACTIONS, actions)]
    mod = parser.OFPFlowMod(
        datapath=datapath, table_id=table_id, priority=priority,
        match=match, instructions=inst,
        idle_timeout=idle_timeout, hard_timeout=hard_timeout
    )
    datapath.send_msg(mod)
```

**参数说明**:
- `datapath`: 交换机数据路径对象
- `priority`: 流表优先级（0-65535）
- `match`: OFPMatch 匹配条件
- `actions`: 动作列表
- `idle_timeout` / `hard_timeout`: 超时时间（秒）
- `table_id`: 流表ID（0-254）

### 1.2 流表删除

**实现位置**: `ble_switch_13.py:delete_flow()`

```python
def delete_flow(self, datapath, match=None, priority=None, table_id=0):
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser

    if match is None:
        match = parser.OFPMatch()

    mod = parser.OFPFlowMod(
        datapath=datapath, table_id=table_id,
        priority=priority if priority is not None else ofproto.OFP_DEFAULT_PRIORITY,
        match=match, command=ofproto.OFPFC_DELETE,
        out_port=ofproto.OFPP_ANY, out_group=ofproto.OFPG_ANY
    )
    datapath.send_msg(mod)
```

### 1.4 统计收集

**实现位置**: `ble_switch_13.py:_stats_collector()`

```python
def _stats_collector(self):
    while True:
        hub.sleep(self.stats_interval)
        for dpid, datapath in list(self.topology['switches'].items()):
            try:
                self.request_port_stats(datapath)    # 端口统计
                self.request_flow_stats(datapath)    # 流表统计
```

## 2. 拓扑管理

### 2.1 自动拓扑发现（LLDP）

**LLDP 发送线程** (`ble_switch_13.py:_lldp_sender()`):
- 定期从每个交换机端口发送 LLDP 数据包
- 默认发送间隔: 5 秒

**LLDP 数据包结构**:
- Chassis ID: 交换机 MAC 地址
- Port ID: 端口号
- TTL: 10 秒
- System Name: `switch-{dpid}`

**LLDP 处理** (`ble_switch_13.py:_handle_lldp_packet()`):

```python
def _handle_lldp_packet(self, dpid, in_port, pkt):
    lldp_pkt = pkt.get_protocol(lldp.lldp)
    if not lldp_pkt:
        return

    chassis_id = port_id = system_name = None
    for tlv in lldp_pkt.tlvs:
        if tlv.tlv_type == lldp.lldp.LLDP_TLV_CHASSIS_ID:
            chassis_id = tlv.chassis_id
        elif tlv.tlv_type == lldp.lldp.LLDP_TLV_PORT_ID:
            port_id = tlv.port_id
        elif tlv.tlv_type == lldp.lldp.LLDP_TLV_SYSTEM_NAME:
            system_name = tlv.system_name

    if chassis_id and port_id and system_name:
        src_switch = system_name.decode('utf-8')
        src_port = int(port_id.decode('utf-8'))
        dst_switch = f'switch-{dpid}'
        dst_port = in_port
        self._add_link(src_switch, src_port, dst_switch, dst_port)
```

### 2.2 拓扑可视化

使用 D3.js v7 在 Web 面板中绘制 SVG 图形：
- **交换机节点**: 蓝色圆形
- **网关节点**: 黄/金色圆形
- **IoT 设备节点**: 绿色圆形
- **普通主机节点**: 灰色圆形
- 支持节点拖拽和缩放

**已知限制**：
- iot1/iot2/iot4 直连 iot3，不经过 OVS 交换机，控制器无法获知其交换机端口位置，拓扑图上显示为 "?" 标记但不连线 — 这是正确的拓扑真实反映
- 设备发现依赖 ARP/ICMP 包触发 Packet-In，通信静默期间拓扑可能不完整

## 4. 协议扩展功能

> **注意**：BLE 扩展框架代码已编写，但**未真正参与路由决策**。`IoTProcessor` 和 `_parse_ble()` 仅解析 BLE 数据并推送到 Web 面板日志，未根据 BLE 数据类型/优先级影响流表下发。当前转发靠普通 IPv4 静态流表。

### 4.1 扩展字段类型

### 4.2 扩展管理器

**实现位置**: `switch/extensions/manager.py`

```python
class IoTExtensionManager:
    def __init__(self):
        self.fields = []

    def add_field(self, field):
        """添加扩展字段"""
        self.fields.append(field)

    def serialize_fields(self):
        """仅序列化字段数据（不含 Experimenter ID），用于 OFPActionExperimenter"""
        data = struct.pack('!B', len(self.fields))
        for field in self.fields:
            data += field.serialize()
        return data

    def serialize_to_experimenter(self):
        """完整序列化: Experimenter ID(4B) + field_count(1B) + fields..."""
        data = struct.pack('!IB', EXPERIMENTER_ID, len(self.fields))
        for field in self.fields:
            data += field.serialize()
        return data

    @classmethod
    def parse_from_experimenter(cls, data):
        """从二进制数据反序列化"""
        exp_id, field_count = struct.unpack('!IB', data[:5])
        ...
        return manager
```

### 4.3 扩展处理流程

**实现位置**: `ble_switch_13.py:process_iot_extension()`

```python
def process_iot_extension(self, ble_type, ble_value):
    if not self.extension_enabled:
        return None
    try:
        # 1. 映射传感器类型
        sensor_mapping = {'temp': 'temp', 'temperature': 'temp',
                          'humidity': 'humidity', 'light': 'light', ...}
        sensor_type = sensor_mapping.get(ble_type.lower(), 'temp')

        # 2. 根据数值计算优先级（值越大优先级越高）
        value_float = float(ble_value)
        if value_float > 80:   priority = 5
        elif value_float > 50:  priority = 4
        elif value_float > 30:  priority = 3
        else:                   priority = 2

        # 3. 创建扩展字段并序列化
        ext_mgr = create_iot_extension(
            sensor_type=sensor_type, device_priority=priority, route_select='route_a')
        extension_data = ext_mgr.serialize_fields()  # 仅字段数据，不含 Experimenter ID

        # 4. 推送到 Web 面板（HTTP）
        field_dict = ext_mgr.get_field_dict()
        requests.post(f"{self.web_panel_url}/api/iot-extension", json=field_dict, timeout=1)

        return extension_data  # 返回给调用方注入 OpenFlow 流表
    except Exception as e:
        self.logger.error(f"处理IoT扩展字段时出错: {e}")
        return None
```

**完整数据流**:

```
BLE UDP 数据包 → _packet_in_handler()
  ├─ 解析 BLE 数据 (addr, type, value)
  ├─ process_iot_extension() → 创建 SensorType + DevicePriority + RouteSelect 字段
  │   ├─ serialize_fields() → 二进制数据
  │   └─ POST /api/iot-extension → Web 面板
  └─ add_flow() 自动安装流表
      └─ actions: [OFPActionOutput, OFPActionExperimenterUnknown(data=extension_data)]
                      ↑ 标准转发        ↑ IoT 扩展字段嵌入 OpenFlow 协议
```

### 4.4 Experimenter 动作注入（v4.5.0 新增）

**实现位置**: `ble_switch_13.py:_packet_in_handler()`

扩展字段不仅上报 Web 面板，还通过 `OFPActionExperimenterUnknown` 嵌入到交换机流表中：

```python
# 自动流表安装时注入扩展字段
if out_port != ofproto.OFPP_FLOOD:
    match = parser.OFPMatch(eth_type=0x0800, ipv4_dst=ip_pkt.dst)
    actions = [parser.OFPActionOutput(out_port)]

    if extension_data:  # 来自 process_iot_extension() 的返回值
        exp_action = parser.OFPActionExperimenterUnknown(
            experimenter=MY_EXPERIMENTER_ID,  # 0xdeadbeef
            data=extension_data              # field_count(1B) + fields...
        )
        actions.append(exp_action)

    self.add_flow(datapath, 10, match, actions, idle_timeout=60)
```

**注入后的流表结构**:

```
OFPFlowMod {
  match:     ipv4_dst=192.168.1.20
  priority:  10, idle_timeout: 60
  actions: [
    OFPActionOutput(port=2),
    OFPActionExperimenterUnknown(experimenter=0xdeadbeef, data=<序列化的IoT字段>)
  ]
}
```

序列化格式: `field_count(1B) + [field_type(1B) + reserved(1B) + value(4B)] × N`

## 6. 智能路径优化

### 6.1 基于应用类型的动态路由

**实现位置**: `ble_switch_13.py:_packet_in_handler()` 和 `_apply_optimized_routing()`

- **高优先级 (≥8)**: 低延迟专用路径

```python
    def __init__(self, app_id, app_name, app_type, app_code,
                 version="1.0.0", description="", requirements=None):
        self.app_id = app_id
        self.app_name = app_name
```
