# SDN IoT 项目安装与启动指南

## 1. 系统要求

- **操作系统**：Ubuntu 20.04 LTS 或更高版本
- **Python**：3.8 或更高版本
- **Node.js**：18 或更高版本（React 前端需要）
- **内存**：至少 4GB
- **磁盘空间**：至少 20GB

## 2. 安装系统依赖

```bash
# 更新系统
sudo apt update && sudo apt upgrade -y

# 安装基础工具
sudo apt install -y git curl wget build-essential

# 安装Python相关依赖
sudo apt install -y python3 python3-pip python3-venv
```

### 安装 Mininet

```bash
sudo apt install -y mininet
sudo mn --version    # 验证安装
```

### 安装 Open vSwitch

```bash
sudo apt install -y openvswitch-switch openvswitch-common
sudo systemctl status openvswitch-switch    # 验证服务
```

### 安装 Ryu 控制器

```bash
# 方法1：使用pip安装
pip3 install ryu==4.34

# 方法2：从源码安装（开发推荐）
git clone https://github.com/faucetsdn/ryu.git
cd ryu && pip3 install .
```

## 3. 项目部署（配置虚拟环境）

```bash
# 在项目根目录执行
chmod +x create_venv.sh
./create_venv.sh

# 激活虚拟环境
source .venv/bin/activate
```

### 安装 Vue 前端依赖

```bash
cd ryu_extend/templates/sdn_dashboard_vue/sdn_dashboard_view
npm install
```

## 4. 启动系统

### 方式一：管理脚本（推荐）

```bash
cd ryu_extend

python3 manage.py start      # 启动完整系统
python3 manage.py status     # 查看系统状态
python3 manage.py stop       # 关闭所有服务
python3 manage.py clean      # 清理环境残留
python3 manage.py gateway    # 仅启动网关
python3 manage.py help       # 查看帮助
```

### 方式二：手动逐个启动（调试推荐）

**后端启动**：

```bash
cd ryu_extend

# 清理环境
sudo mn -c
sudo lsof -i:6634 -t | xargs -r sudo kill -9 2>/dev/null || true
sudo lsof -i:5000 -t | xargs -r sudo kill -9 2>/dev/null || true
sudo ovs-vsctl del-br s1 2>/dev/null || true
sudo ovs-vsctl del-br s2 2>/dev/null || true

# 终端1：启动控制器
ryu-manager switch/ble_switch_13.py --verbose --ofp-tcp-listen-port 6634

# 终端2：启动 Flask API 服务器（React 版）
python3 templates/sdn_dashboard_vue/sdn_dashboard_server/server.py

# 终端3：启动网络拓扑
sudo python3 topology/iot_sdn_topology.py
```

**前端启动（开发模式）**：

```bash
# 终端4：启动 React 开发服务器
cd ryu_extend/templates/sdn_dashboard_vue/sdn_dashboard_view
npm run dev
```

**访问地址**：
- 开发模式：http://localhost:5173（Vite 开发服务器，自动代理 API 到 5000）
- 生产模式：http://localhost:5000（Flask 直接托管 React 构建产物）

## 6. Web 面板使用指南

### 6.1 系统概览

展示交换机在线状态、BLE节点状态、拓扑链接数量、系统状态、更新时间。

### 6.2 拓扑可视化

使用 D3.js 绘制网络拓扑图：
- 交换机：蓝色圆形
- 主机：绿色圆形
- 链接：蓝色线条
- 支持节点拖拽和缩放

### 6.3 流表管理

**添加流表**：
1. 选择目标交换机（s1 或 s2）
2. 输入流表 ID（默认 0）、优先级（默认 10）
3. 输入匹配条件，例如：`eth_type=0x0800,ipv4_dst=192.168.1.20`
4. 输入动作，例如：`output:2` 或 `drop`
5. 点击"添加流表"

**清空流表**：选择目标交换机 → 输入流表ID（留空则清空所有） → 确认

### 6.4 统计数据

展示端口统计（收发包数、字节数）、流表统计（匹配次数）、流表统计（活跃数）。每10秒自动更新。

### 6.5 日志监控

展示网关数据传输日志、s1/s2交换机数据传输日志。

### 6.6 边缘应用管理（接口骨架）

> **注意**：此功能仅有 Web 面板 UI 和控制器 API 接口骨架，未真正实现应用推送到设备执行。

**创建应用**：指定应用ID、应用名称、应用类型（1=数据过滤，2=AI推理，3=数据聚合，4=自定义）、应用代码。

**部署应用到设备**：指定应用ID和目标设备ID。

**卸载应用**：指定应用ID和设备ID。

### 6.7 设备角色管理（接口骨架）

> **注意**：此功能仅有接口骨架，`DeviceRoleManager` 未真正实现设备角色切换逻辑。

**注册设备**：指定设备ID、设备名称、初始模式（1=纯转发，2=计算混合，3=物联网网关）。

**切换设备角色**：指定设备ID、目标模式、是否强制切换。

**识别最优模式**：指定设备ID、流量模式（可选）、资源使用情况（可选）。

## 10. 故障排查

### 常见问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| `Address already in use` | 端口被占用 | `python3 manage.py clean` |
| `Permission denied` | 权限不足 | `sudo python3 topology/iot_sdn_topology.py` |
| `No module named 'ryu'` | 环境问题 | 确保 `source .venv/bin/activate` |
| `RTNETLINK answers: File exists` | 网络接口冲突 | `sudo ip link delete s1` |
| `could not connect to controller` | 控制器未运行 | 检查 `sudo lsof -i:6634` |
| 网关无法转发数据 | iptables/ip_forward问题 | 检查 `iptables -t nat -L` 和 `sysctl net.ipv4.ip_forward` |
| IoT跨子网ping不通(如iot1→h1) | 控制器未运行或流表未预装 | 先启动控制器再启拓扑；检查流表 `ovs-ofctl dump-flows s1` |
| 拓扑不显示主机 | ARP未触发设备发现 | ping 一次触发 ARP 交换后刷新拓扑 |
| 拓扑只显示交换机无主机 | 主动流表模式下IPv4不走Packet-In | 已修复(v4.5.2)：从ARP包提取IP做设备发现 |
| `nc -u` 命令卡住不返回 | UDP无连接关闭信号 | 加 `-w 1` 参数设置1秒超时 |
| 端口6634冲突 | 需要清理 | `sudo lsof -i:6634 -t \| xargs -r sudo kill -9` |
| 网关日志显示 Connection refused | iot3命名空间内无法访问宿主机127.0.0.1 | 不影响功能，控制器已自行预装流表 |
| Vue拓扑IoT设备有节点无连线 | iot设备直连网关不在OVS交换机上 | 正常行为，非bug |

### IoT跨子网连通性排查

当 iot1/iot2/iot4 无法 ping 通 h1/h2 (192.168.1.20/21) 时，按以下步骤排查：

```bash
# 1. 检查 iot3 NAT 规则（应有3条 MASQUERADE）
mininet> iot3 iptables -t nat -L POSTROUTING -n -v

# 预期输出包含：
# MASQUERADE  all  --  192.168.2.0/24  0.0.0.0/0
# MASQUERADE  all  --  192.168.3.0/24  0.0.0.0/0
# MASQUERADE  all  --  192.168.4.0/24  0.0.0.0/0

# 2. 检查 IP 转发
mininet> iot3 sysctl net.ipv4.ip_forward
# 预期: net.ipv4.ip_forward = 1

# 3. 检查 conntrack 模块
mininet> iot3 lsmod | grep nf_conntrack
# 应有 nf_conntrack 和 nf_conntrack_ipv4

# 4. 检查流表
mininet> sh ovs-ofctl dump-flows s1 -O OpenFlow13
mininet> sh ovs-ofctl dump-flows s2 -O OpenFlow13

# 5. 抓包分析 — 在 iot3 上同时抓所有接口
mininet> iot3 tcpdump -i any -n 'icmp' &
mininet> iot1 ping -c 3 192.168.1.20
```

**常见根因**:
- **NAT规则缺失**: iot3 的 `iptables -t nat -L` 无 MASQUERADE → 确认 `iot_sdn_topology.py` 中已添加 NAT 规则
- **conntrack 未加载**: 回程包无法 de-NAT → `modprobe nf_conntrack; modprobe nf_conntrack_ipv4`
- **route_engine 无回程路由**: 192.168.2.x/3.x/4.x 目的 IP 匹配不到路由 → 确认 `route_engine.py` 包含 IoT 子网路由

## 11. 最佳实践

- 使用合理的流表优先级（高优先级先匹配）
- 合理设置 idle_timeout 和 hard_timeout
- 定期清理过期流表，避免影响性能
- 合理设置统计收集间隔（建议5-30秒）
- 使用防火墙限制控制器访问IP
- 定期检查日志，发现异常行为
- 生产环境建议使用 TLS 加密 OpenFlow 连接

## 12. 常见问答

**Q: 如何重置系统状态？**
A: 访问普通面板，点击"清空数据"按钮，或调用 `/api/clear-data` API

**Q: 支持哪些 OpenFlow 版本？**
A: 目前仅支持 OpenFlow 1.3

**Q: 如何修改统计收集间隔？**
A: 修改 `ble_switch_13.py` 中的 `self.stats_interval` 值

**Q: 如何查看详细的调试日志？**
A: 启动控制器时添加 `--verbose` 参数
